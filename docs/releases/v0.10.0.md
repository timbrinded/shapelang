# Shape v0.10.0

Shape v0.10.0 makes change review stricter: attestations must belong to the
current change, guarded functions react to edits in their source files, and
the checker can identify rule edits that are what let a change pass.

## Change review

- Add `--base-ref` and `--base-model` to compare attestations with the base
  model. Unchanged attestations produce stale warnings and no longer satisfy
  coverage or docs bindings for a new change.
- Add `shp attest prune` to remove those stale attestations, including ones
  inside change blocks, while preserving attestations written for this change.
- Add `shp check --check-loosening` with a base model. It restores edited or
  removed rule-layer declarations one at a time and reports edits whose
  restoration brings back a check failure.
- Require a fresh reevaluation when a changed-file list includes a guarded
  function's source file, even when the function's Shape declaration is unchanged.
- Add opt-in `--check-cited-paths` validation for source and evidence paths,
  including generated function and candidate-effect citations.
- Reject unknown `on_change` values instead of silently ignoring them.

## Analyzer fixes

- Recognize PostgreSQL named and non-ASCII dollar-quote tags without opening
  quotes inside identifiers.
- Decode TypeScript raw-SQL string escapes before analysis, including line
  continuations, while retaining source locations for hints. This fixes both
  missing destructive-statement hints and false hints inside quoted SQL bodies.

The analyzer remains advisory. PostgreSQL function and DO bodies inside dollar
quotes are not analyzed, and SQLite parameters shaped like `$name$` can be
interpreted as PostgreSQL dollar quotes.

## Upgrading

Use the same base commit for the changed-file list and `--base-ref`. Update
the authored model when architecture changes; write a narrow current attestation
only when the contract did not change. Run `shp attest prune --base-ref <base>`
to remove old attestations.

Stale-attestation warnings alone do not fail a check, but an old attestation no
longer excuses a new governed-source or bound-docs change. A guarded source edit
needs a reevaluation written for that change. Review existing `on_change` values
if upgrading exposes a previously ignored spelling.

`--check-loosening` and `--check-cited-paths` are opt-in. These checks validate
declared claims and review obligations; they do not prove implementation correctness.

## Plugin and documentation

The coordinated 0.10.0 plugin teaches current attestation, pruning, and
rule-loosening workflows. The documentation has been reorganized around a
consistent example, with new diagrams and concept videos.

## Distribution and release verification

The release includes Linux x64, Linux ARM64, macOS ARM64, and Windows x64
archives, version-specific installers, and SHA-256 checksums. Candidates now
smoke-test packed binaries on every supported platform before tagging and run
skill canaries against the packed Linux x64 binary. Release builds stop when
parser metadata cannot be read or the archive-target list is empty.

Publication requires both coordinated tags on current master and an approved
candidate for that exact commit. Published assets, notes, checksums, installers,
and setup-action installation are verified after publication.
