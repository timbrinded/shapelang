# E10: mutation testing Shape's own model

E10 borrows PDD Kit's vacuity check ("every spec clause must be broken by some
mutant") and turns it on the repository's own architecture model. Which claims in
`shape/*.shape` catch no plausible architectural change, and which kinds of change
does no claim catch? Numbers are as measured on 2026-10-23. `results.json` holds the
aggregate and `tables.md` the full tables. The per-mutant data (about 80 MB) is
regenerated by the scripts.

## Setup

- **Snapshot.** A copy of `shape/` at `b52cb5b`. The six authored files are identical
  at `12391bd`, which added only generated-AST files.
- **Oracle.** `shp check` with default discovery (222 files) run from source; the
  baseline passes with no diagnostics, identically over 5 runs.
- **Authored model.**
  - 24 components, 79 resources, 101 functions with 572 effect entries, 181 grants, 47 `owns`.
  - 73 relations: 52 `calls`, 20 `provides`, 1 `coordinated_call`.
  - 5 rules with 18 clauses: 14 `forbid provides`, 1 `forbid hypercycle over calls`, 3 `forbid path … -> ExperimentalSemanticKernel over calls`.
  - **No final forbids:** no authored resource carries a trait, and no rule has `forbid final`.

## Operators

| Operator | Mutants | Killed | Score | Killing diagnostic |
|---|---:|---:|---:|---|
| M1 add an effect to a fn (every fn × 10 prelude effects × 79 resources) | 79,415 | 78,388 | 98.7% | `missing grant` only |
| M2 remove a grant | 181 | 179 | 98.9% | `missing grant` |
| M3 add a `calls` edge | 502 | 172 | 34.3% | hypercycle 148, path 68 (44 hit both) |
| M4 add a `provides` edge | 1,876 | 322 | 17.2% | `forbidden provides` |
| M3/M4 involving a generated-AST declaration (sampled) | 120 | 0 | 0% | none |
| Destructive effect plus a matching grant (probe) | 237 | 0 | 0% | none |
| The same with `: AppendOnly` on the resource (control) | 79 | 79 | 100% | `forbidden effect` |

M1 is predicted exactly by one fact: a mutant survives iff its component already
grants that effect. Every effect no component grants (Redact, LogicalDelete,
HardDelete, Truncate, DropStorage, Export, Import) is always killed. Batched M1 runs
were checked against 80 single runs (80/80 agree). Reruns were byte-identical, and
there were no crashes.

## Vacuous claims

- **Rule clauses:** none is vacuous. Each `forbid provides` clause kills 23 mutants (one per other component).
- **Redundant path clauses:** two of the three `forbid path` clauses in
  `ExperimentalSemanticKernelIsolation` are redundant under edge additions. Their kill
  sets nest (40 ⊂ 48 ⊂ 68) because `ShpCli` reaches `ShapeEditorServices`, which
  reaches `ShapeChecker`.
- **Grants:** 2 grants are unused, `ShapeRuleEngine grants Update<ShapeHypergraph>` and
  `DocsSite grants Update<DocsContent>`.
- **`owns`:** the 47 declarations never take part in any diagnostic.

## What no claim catches

1. **Destructive effects.** A destructive effect plus its grant passes on all 79 resources,
   because none carries a trait. With `AppendOnly` added, all are rejected.
2. **Effects spreading inside a component.** All 1,027 M1 survivors are a fn gaining an
   effect a sibling already has, since a grant covers the whole component.
   - `ShapeRuleEngine.deriveFinalForbidsForResource` can gain `Read<FactSet>` and
     `Append<SemanticDiagnostics>`, against its own description.
   - Seven more `ShpCli` fns can gain `Read<SystemClock>`, against memory `ClockReadAtCliBoundary`.
3. **New `calls` coupling.** All 148 back-edges are rejected; 0/98 shortcuts and 232/256
   new couplings pass. 47 edges from core checker/language components to tooling
   components pass, for example `ShapeChecker -> ShapeAuthoring`. Two boundaries stated
   only in prose pass: `ShapeAnalyzer -> ShapeChecker` and `ShapeAuthoring -> ShapeChecker`.
4. **Kernel isolation.** A direct `calls` edge into `ExperimentalSemanticKernel` passes
   from `ShapeIncrementalChecker`, `DocsSite`, `DocsShapeBlockVerifier` and
   `ReleasePipeline`. Any `callbacks` or `coordinated_call` route into it passes.
5. **Providers.** 65 of 79 resources have no provider-exclusivity rule; 1,554 `provides`
   mutants pass, 897 of them a non-owner providing an owned resource.

## CI mode

With `--changed-files` and a base model, docs bindings reject several survivors, but
only because a bound docs file was not edited: listing one docs file clears them, and
`delivery.shape` has no binding. A destructive effect plus grant in `delivery.shape`
also passes `--check-loosening`.

## Threats to validity

- **Plausibility.** The enumerations include implausible mutants, and M1 is dominated by effects nothing grants.
- **Additions only.** No deletion operators were run, so redundancy holds under additions only.
- **Oracle scope.** The oracle is plain `shp check`; coverage, cited paths and `shp obligations` are outside it.

## Run

Copy `e10/` and the repository's `shape/` into a work directory
(`<work>/scripts`, `<work>/shape`), then from `<work>`:

```text
bun "$SHAPELANG_DIR/packages/shp-cli/src/index.ts" inspect --json > inspect_full.json
python3 scripts/gen_mutants.py && python3 scripts/gen_hocontrol.py && python3 scripts/followups.py
scripts/run_all.sh && scripts/run_followups.sh
python3 scripts/analyze.py && python3 scripts/tables.py
```
