# Shape's own model in 1.0 form (dogfood)

Root: `experiments/shape-1/dogfood/`. Run every command from the repo root. The tools use the prototype (`experiments/shape-1/proto/src`) as a library.

## Files

### The model

- `shape1.yaml` (724 lines): the authored 1.0 sidecar, written as an overlay on the migrated 0.x model. It is a `shape.source.v1` document plus an `x-overlay` section:
  - `renameModules` renames `shape1.migrated` to `shape.governance`, including every reference.
  - `drop` removes migrated declarations. Here it drops the 47 `std::Owns` rules, the migrated shape and the migrated actors.
- Merge rules:
  - A declaration with the same (module, decl, name) as a migrated one is merged field by field.
  - `units` merge by unit name.
  - Every other array replaces the migrated one.
  - `null` deletes a field.
  - A new declaration is appended to its module.
- `model.source.json`: the complete 1.0 model, generated by `tools/compose.ts`.
- `model.shape1` (1,923 lines) and `shape1.shape1` (807 lines): the full model and the overlay printed in 1.0 surface syntax. The extension is not `.shape`, because `format:shape` would run the 0.x formatter on them.

### Laws

- `laws/*.law.test.ts`: one bun test per law, named by the law's claim id (for example `shape.checker::FinalForbidBeatsGrant`).
- `laws/lawkit.ts`: seeded mulberry32 generators and `property()`.
  - `lawTest(id, "holds" | "fails", run)` appends the verdict to `$SHAPE_LAW_RESULTS` (JSONL): `{law, holds, cases, seed, counterexample: {index, detail} | null}`.
  - It asserts the expected verdict, so `bun test` stays green while a contradicted law is documented by its counterexample.

### Providers (`providers/`)

Seeds are sha256("shape-dogfood-provider-<name>"). They are fixed dogfood values, not secrets, and the public keys are declared in `shape1.yaml`.

- `bun-test.ts` (`shape.governance::bunTest`)
  - Runs the law tests and emits one Test Result record per law:
    - `code` = Req: the bound unit, at `unit`.
    - `harness` = the law files the test imports, at `file`.
    - `deps` = the repository files the test imports.
    - `counterexample` and `bound {cases, seed}` come from the verdict.
  - Laws it decides by template but has no test for get an `inconclusive` record, so E-provider-missing does not fire.
  - Soundness: presence.
- `ts-clock-scan.ts` (`shape.governance::tsClockScan`)
  - Observes `effect(ts.call("Date.now" | "Date" | "performance.now" | "process.hrtime"))` in every ts/js identity, with one file-level scope entry per file.
  - An entry is complete only when every mention of Date, performance or hrtime in the file is a direct call, `Date.UTC`, `Date.parse` or a type.
  - Soundness: presence and absence.
- `ts-calls.ts` (`shape.governance::tsCalls`)
  - Emits call facts between manifest identities, resolved with the TypeScript type checker.
  - Calls whose resolved declaration is not a code identity are dropped. That includes members of object types, such as calls through injected `services` objects.
  - Entries are never complete. Soundness: presence.
- `ts-ident.ts`: TypeScript identity spans, named exactly as the prototype manifest names them.
- `common.ts`: citations, signing, JSONL output, and record time (`now` minus 1 h).

### Tools (`tools/`)

- `compose.ts [--check]`: writes or verifies `model.source.json`, and prints counts and elaboration errors.
- `provide.ts --out <dir> [--root <tree>] [--now T] [--only bunTest,tsClockScan,tsCalls]`
  - Writes `<dir>/<provider>.jsonl` as DSSE envelopes, and `<dir>.summary.json` outside the directory.
  - The default head is the working tree's tracked files plus the dogfood files.
- `check.ts <mode> [--records d] [--base-records d] [--authors json] [--reviews json] [--now T] [--out f] [--input-out f] [--human] [--teeth] [--partial-summaries]`
  - `audit`: no base.
  - `adopt`: the base is the migrated 0.x model with no overlay; the head is the dogfood model.
  - `adopt-governance`: step 1 of 2. It adds the shape.governance module, drops the Owns rules, and lands the rebinding of the 4 units that 0.x bound to shared files (`STEP1_REBINDS`) plus their components' path globs. Without the rebinds the step-1 head carries the migrated base's 2 E-overlap and 6 E-conduct errors.
  - `adopt-content`: step 2, from step 1's head to the dogfood model.
  - `--partial-summaries` reads every `effects complete` summary as `partial`.
  - Prints a summary (`summary.ts`) and writes the full `shape.check.output/v1`.
- `runs.ts replay <rev>... | scenario <name>... --work <dir> [--out <rows.json>]`
  - Materialises base and head trees (`git archive` plus the current dogfood files).
  - Composes each tree's model and runs the observers on both trees, and all three providers on the head.
  - Derives, and writes `<label>.out.json`, `<label>.human.txt` and the rows JSON (default `<work>/<cmd>.rows.json`).
  - Scenarios: `readme-only`, `refactor-isoToday`, `seed-clock-freshness`, `break-codepoint-order`, `edit-law-harness`, `edit-checkCoverage`.
- `print.ts [--overlay] [--model f] [--out f]`: the 1.0 surface-syntax printer for `shape.source.v1`.
- `lib.ts`: `composeModel(manifest, overlay?, shapeDir?)`, `manifestFor(files)`, `workingTreeFiles()`, `materialize(rev, dir)`, `treeFiles(dir)`, `claimIndex`, `unitBindings`, `readOverlay`, `readModel`.

## Conventions for other agents

- A law test's name is the claim id, and its file must contain the id as a string literal; bunTest finds the test file that way.
- Records are tied to a revision. Editing any dogfood file, tools included, changes the tree id, so rerun `provide.ts` before `check.ts`.
- `--records` must point at a directory holding only records. A non-record JSON containing a float crashes the prototype's derive (see open problems).

**Open problems**

- Awkward point 1, the sidecar. The prototype's `--sidecar` replaces a whole declaration by (module, decl, name). Setting a tier or a boundary flag on a component therefore means restating all its units, and a migrated declaration cannot be removed. I wrote my own overlay merge (tools/lib.ts composeModel). As a result the dogfood model reaches derive through my tools, not through `shape1 check --model . --sidecar`.
- Awkward point 2, governance compared with content. Shape's 49 in-memory 'resources', 31 of them bound to TS types, fit the 1.0 effect and authority vocabulary poorly. Their Read, Append and Update effects describe data flow inside a pure library, which no observer can verify. `data_flow` relations would be the more honest 1.0 form, but migration preserves the effects. No provider observes ts.type, fs.path, http.route, gha.*, git.ref, proc.exec or md.fence, so 75 of the 82 codes are documentation, and their channels turn into coverage obligations.
- Awkward point 3, laws and judgment. The 29 untested clause laws are tier normal ('law debt'), so edits to their units do not block. Making them critical would block every change to those units until a test exists. The Property template means a test author decides how the law is read. FormatterCanonicalGraphRules (kind order) and FinalForbidTargetsDeterministic are examples where the stronger and weaker readings of the same text give different verdicts.
- Findings in Shape's code from this run.
(a) The memory FormatterCanonicalDiffs is out of date: the grammar accepts only grouped who/when/guards blocks.
(b) The formatter keeps kind filters in the order written, so `over calls or callbacks` and `over callbacks or calls` format differently.
(c) final_forbidden_effect diagnostics name the first trait in the resource's attachment order: `R : A, B` names A, while `R : B, A` names B.
(d) `Date.now()` in update's replaceWindowsBinary violates ClockReadOnlyAtCliBoundary. It is now debt under exception UpdateTempTokenReadsClock, which expires 2027-04-30. It also means ShpCli.updateInstalledBinary's complete summary omits Read<SystemClock>, but the checker does not detect that: runUpdate calls replaceBinary through the injected `services` object, the type checker resolves the call to a member of the UpdateServices type, and tsCalls drops it. So no call fact links update or runUpdate to replaceBinary.
(e) performance.now reads violate authority in 6 identities of the unix-system-visualiser plugin renderer (attributed to CiPipeline through the 0.x skill glob) and in experiments/semantic-kernel/harness/benchmark.ts#medianDuration. The benchmark read is also the only effects.upper contradiction witnessed by an observed effect, against benchmarkCandidateFingerprintPrototype's summary.
- Call observers and dependency injection. Neither tsCalls nor observe-ts links a call made through an injected services object to the function that implements it (observe-ts reports 29 calls as 'unresolved:interface-or-field'). So complete summaries cannot catch drift reached that way, as with update's Windows Date.now. A provider would need to resolve object-literal implementations of an interface (here defaultUpdateServices) or declare such calls incomplete.
- The dogfood was not committed when these measurements were taken. The 'head' was therefore the working tree's tracked files plus experiments/shape-1/dogfood/**, and every dogfood edit, tools included, changes the tree id and stales all records. This pass's check.ts edit added 1 tsCalls fact (2,747 to 2,748) and changed no audit key. The replays use today's overlay and today's dogfood laws over historical trees, with each tree's own 0.x shape files.
- The 337 effects.upper contradictions are left in the model on purpose. Fixing them means either reading summaries as partial, which loses 101 upper bounds, or rewriting the summaries by hand to be transitive.
- Prototype bug: readEvidence loads every .json file in a records directory. A non-record JSON containing a float, such as a summary with 'seconds': 3.6, makes derive throw in JCS instead of being rejected as RJ01.

**Spec feedback from the build** (folded into the final spec; see [RFC.md](../RFC.md))

- Effect summaries. 1.0 `effects complete` is a transitive upper bound over calls (effects.upper, Xt(u) over reach(u)), but 0.x `effects complete` lists only a function's own effects. Migrating 0.x summaries as `complete` gave 337 sound effects.upper contradictions on Shape once a presence-sound call observer ran. 336 are witnessed by 1 to 9 call hops to an atom a callee's summary declares. Only 1 is witnessed by an observed effect: performance.now at experiments/semantic-kernel/harness/benchmark.ts#medianDuration (0 hops), against ExperimentalSemanticKernelHarness.benchmarkCandidateFingerprintPrototype's Read<SystemClock>. Either add a direct-effects summary mode, or have migrate map 0.x complete to `partial`. Reading them as partial leaves 11 contradictions.
- Effect forbids and transitive summaries. An effect.forbid reads each unit's declared summary atoms, and complete summaries are transitive. So `forbid Read<SystemClock> ... except unit ShpCli.isoToday` is E-conduct until every unit whose summary reaches isoToday (here ShpCli.main) is also excepted. The pattern 'only X may do V' needs an except list that tracks the call graph.
- When a law obligation counts as introduced. It is introduced only when Req meets Δcode, and for a TS unit Req is the unit digest, which includes the names it references but not the bodies of its callees. Making compareCodepointStrings locale-aware made the InspectionCodepointOrder test contradict (a sound contradiction), yet the obligation came out preexisting and owed. Only an unrelated coverage obligation blocked the change. Count the contradicting record's deps or cone against Δcode, or widen test Req to the unit's call cone. As written, H3 does not hold for bugs located in callees.
- E-provider-missing granularity. A provider declares `decides template T`, so once it is authenticated in the base, every instance of T needs a record each run. Before bunTest emitted inconclusive records this gave 52 E-provider-missing errors. After that, 3 remained, all for laws on units bound to whole files (item 6), and I retargeted those laws to function units. Either let a provider declare the instances it decides, or state that `inconclusive` satisfies E-provider-missing (the prototype accepts it).
- No hosted statements in TypeScript. The closure projection exists only for Verus, so every TS law must be a template instance. 45 of the 50 testable laws use one generic `Property<F: unit, Statement: value>`. The law's meaning is a string plus the provider's test. schemaFp does not cover the statement text, and rewording it creates a new claim (L4 removal). A hosted-test form for TS, or a closure projection for TS units, would let the shape cite the test.
- Units bound to files or raw identities cannot carry tested laws. Test Req is (bind(u), unit), and files and raw identities have no unit projection. This hit ShapePreludeRegistry.definePreludeMetadata (bound to prelude.ts) and ShapeGrammar.generateAst (bound to shape.langium). Either allow `file` or `own` projections for test Req, or make this an E-route error up front.
- Resource-code value matching. Values are compared as exact canonical strings, with `*` allowed only in channels. 9 of the 26 fs.path codes are globs, and a fact at a concrete path can never map to them. Path-like kinds need glob or prefix semantics in the registry.
- Defaults for unregistered resource-code kinds. A kind the registry does not know is treated as carried by every language and every raw executable. Authority claims take effect(t) channels for every bound code, so binding 82 codes (31 ts.type) means every change to a governed component needs coverage on channels no observer supplies. This produced blocking critical coverage in 5 of 6 scenarios, in 4 of 8 replayed commits, and in step 2 of the adoption (4 components). Unregistered kinds should default to no carriers, or to declared carriers.
- Path globs have no exclusion. Test files under `packages/shp-checker/src/checker/**` belong to ShapeChecker. An observed call from checker/incremental.test.ts closes a `calls` cycle, a sound and blocking false positive. A `**/*.test.ts` component is less specific than the existing globs, so it cannot reclaim the tests. `paths` needs excludes, or test code needs its own classification.
- L7 fan-out. One owner move, from shape1.migrated::Maintainers to shape.governance::ShapeMaintainers, gives 558 separate L7 items in step 1: 351 claims, 101 units, 79 resources, 23 components and the shape. Lowering three components to tier low gives 33 L7 rows (23 claims, 7 units, 3 components). Owner and tier changes should be reported once, where the inheritance starts. Actors also need `was`, so that a rename can be matched.
- Tier final and one-person projects. Tier final needs two distinct persons, one from the base owner and one from the shape owner. A single-maintainer project like Shape cannot use final at all (E-policy).
- Hatch kinds for TypeScript. The TS hatch kind ts_ignore counts only @ts-ignore. The manifest showed 0 markers, while the repo has 2 @ts-expect-error in packages and 17 @ts-nocheck files in experiments. std also declares `unsafe` only for Bend, not for Rust. So ReviewedSurface `at trust` on a TS boundary has an empty Req and is vacuous; I did not attach it.
- Workflow jobs are not identities. A unit for a multi-step CI job can bind only one step. This forced the fixes for the 2 genuine E-overlaps: runShapeCi binds jobs.shape.steps.5 and runExperimentalSemanticKernel binds jobs.semantic-kernel.steps.6. Because the migrated base carries these overlaps, any staged adoption must land the rebinds, and the owning component's path globs, in its first step, or that step's head does not elaborate (8 errors: 2 E-overlap and 6 E-conduct).
- Migrating `owns`. migrate maps 0.x `owns` to std::Owns, an exclusive writer plus a provides forbid. The 0.x glossary says owns is 'only name-checked ... not exclusive'. This mints 47 rules that 0.x never claimed, which cause 35 of the 43 baseline errors. Removing them costs 92 loosening rows against a migrated base (47 L1 + 45 L3+L6).
- Alias resources. Two resources may not bind the same code. 0.x has 5 alias pairs where one name is used in effects and the other only in `forbid provides`: EffectiveModel/EffectiveShapeModel, FactSet/ShapeFacts, SemanticDiagnostics/SemanticDiagnosticSet, DiagnosticText/HumanReadableDiagnostics, FormattedShape/CanonicalShapeFormat. The alias names stay unbound.
- DocumentedBy takes a single Doc. A 0.x binding requires that some one of N docs changed. The 7 bindings became 10 one-doc laws, and the either-or meaning is lost.
- No claim form for call order inside a body. 5 call-graph clauses (CheckPipelineOrder, SharedCheckPipelineOrder, LoweringBeforeRules, UpdateBinaryIntegrity, CliCommandDispatchOrder) have no 1.0 form and stay as judged RefactorSensitive laws. Only 1 of the 11 call-graph clauses (AnalyzerCheckerSeparation) became a structural rule (`forbid path`).
- Policy blocks in audit mode. In audit mode there is no base, so rules 6 and 7 make every sound contradiction block, and critical policy blocks every unestablished critical law. A real repository with any drift is therefore always blocked in audit (here 365 of 414).
